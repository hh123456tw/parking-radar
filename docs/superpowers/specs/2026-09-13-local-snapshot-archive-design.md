# 停車快照 VM 本機封存設計

日期：2026-09-13  
狀態：待使用者確認

## 目標

網站與歷史圖繼續只查 MySQL 最近八天的快照，同時把即將從 MySQL 清除的完整歷史資料壓縮保存在 VM，供未來 Pandas 與機器學習離線使用。封存功能不得增加一般查詢路徑的工作，也不得在封存失敗時刪除資料。

## 範圍

- 保留臺北市單一城市版本與現有查詢、推薦、PWA、歷史圖。
- 每天由既有 `snapshot_cleanup.py` 排程先封存、驗證，再刪除。
- 封存位置預設為 `/opt/parking-archives`。
- 不建立 GCS Bucket、不修改 VM 服務帳號、不加入網站查詢封存檔功能。
- 2026-09-12 清理前的資料仍只保存在既有 SQL 備份，本次不自動還原或轉換該備份。

## 資料流程

```text
臺北市 API
  → 每 15 分鐘寫入 MySQL parking_snapshots
  → 每天 03:23（Asia/Taipei）執行封存清理
  → 找出超過八天且已完整結束的 UTC 日期
  → 串流寫入暫存 CSV.gz
  → 驗證 gzip、CSV 標頭與資料列數
  → 同目錄原子改名為正式檔
  → 分批刪除該日期在 MySQL 的快照
```

只處理完整 UTC 日期，因此 MySQL 實際會保留至少八天、最多接近九天；這比切割半天檔案更容易理解與重跑，也不影響七天歷史圖。

## 封存格式

每個 UTC 日期一個 gzip 壓縮 CSV：

```text
/opt/parking-archives/YYYY/MM/parking-snapshots-YYYY-MM-DD.csv.gz
```

欄位固定為：

1. `lot_id`
2. `lot_name`
3. `district`
4. `total_spaces`
5. `available_spaces`
6. `source_updated_at`
7. `captured_at`

停車場名稱、行政區與總車位一起保存，避免未來基本資料變動後無法重建當時的訓練資料。時間維持資料庫 UTC 值，分析時再轉為臺北時區。

## 元件與責任

### `snapshot_archive.py`

- 找出可封存的完整日期。
- 用伺服器端串流游標分批讀取，不把一天資料全部載入 1 GB VM 記憶體。
- 使用 Python 標準庫 `csv`、`gzip` 寫檔，不增加套件。
- 寫入同目錄暫存檔，完成驗證後才原子改名。
- 正式檔已存在時，驗證其 gzip 與標頭後視為可安全重跑，不覆寫。
- 封存前檢查磁碟剩餘空間；低於 1 GiB 時停止且不刪資料。

### `snapshot_cleanup.py`

- 保留既有每日 CLI 入口與八天保留規則。
- 逐日呼叫封存；只有該日封存成功後才分批刪除該日資料。
- 每批刪除一萬筆並提交，縮短鎖定時間。
- 任一日期失敗即停止，較新日期不繼續處理。
- 輸出封存日期、封存列數與刪除列數，供 cron 日誌檢查。

### `database.py`

- 提供最早快照時間、每日資料列串流及指定日期範圍的分批刪除。
- 所有時間與批次大小維持參數化 SQL。

## 失敗與重跑

- 下載／寫檔／壓縮／驗證失敗：刪除暫存檔，不刪 MySQL。
- 磁碟不足：立即失敗，不刪 MySQL。
- 正式封存檔已完成但刪除中斷：下次驗證既有封存檔後繼續刪除，不重複寫檔。
- 正式封存檔損壞：停止並保留 MySQL，不自動覆蓋，以免掩蓋磁碟問題。
- 單日沒有快照：不建立空封存檔，也不執行刪除。
- 網站與 Collector 不依賴封存成功；封存失敗只會讓 MySQL 暫時保留更多舊資料。

## 部署與還原

1. 部署前備份目前應用程式、資料庫及 parking 使用者 crontab。
2. 建立 `/opt/parking-archives`，僅讓 `parking` 使用者與管理者存取。
3. 保留原本每日 03:23（臺北時間）的 `snapshot_cleanup.py` 排程。
4. 先以指定測試目錄執行一次封存清理，驗證檔案後再切換正式目錄。
5. 正式部署後檢查 gzip、CSV 標頭、列數、MySQL 日期範圍及網站查詢。
6. 應用程式可用原子切換留下的目錄回復；資料庫在封存後只刪除已有驗證檔的資料。

## 測試與驗收

- TDD 驗證完整日期邊界與八天保留規則。
- 使用真實暫存目錄驗證 CSV.gz 內容、Unicode、標頭及原子檔名。
- 驗證磁碟不足、損壞既有檔、寫入例外都不會呼叫刪除。
- 驗證封存成功後才逐批刪除，且失敗交易會回滾及關閉連線。
- 完整 pytest、Python compileall、JavaScript syntax 與 GitHub Actions。
- 正式環境驗收：封存檔可解壓、資料筆數符合、MySQL 僅保留近期資料、臺北車站與手動查詢均低於前端 20 秒限制。
