# 停車決策圖卡設計規格

## 目標

把目前偏工程數據的「推薦與避雷」區塊改成第一次使用者也能立即理解的決策圖卡。圖卡優先回答「要不要去」及「為什麼」，並補上完整地址、剩餘／總車位、Google 地圖與歷史資料入口。

本次只改善既有單頁結果呈現與固定規則說明，不加入新的外部 API、AI 推薦或預測模型。

## 設計原則

- 結論優先：圖卡第一行顯示「建議前往」、「有滿場風險」或「不建議前往」。
- 理由可驗證：每個原因只能來自官方空位、總車位、距離或既有歷史樣本。
- 數字降級：`hell_score` 改稱「停車壓力」，`recommendation_score` 改稱「綜合推薦」，精確分數只放在卡片底部的計算細節。
- 不依賴 Gemini：Gemini 維持只解析對話意圖、目的地、行政區與時間，不產生分數、原因或停車場資料。
- 不增加畫面負擔：維持三欄桌面版與單欄手機版，不新增頁面或大型前端框架。

## 圖卡內容與順序

每張圖卡由上到下顯示：

1. 狀態徽章與排序角色，例如「建議前往／首選」。
2. 停車場名稱。
3. 完整地址。地址是可點擊連結，另開 Google 地圖。
4. `剩餘車位 / 總車位`，例如 `5 / 5 格目前可停`。
5. 空位比例條及與目的地的距離；行政區模式顯示「行政區比較」。
6. 「為什麼推薦／為什麼要小心／為什麼不建議」及最多三條固定規則原因。
7. 「Google 地圖」與「查看歷史」兩個獨立操作。
8. 次要計算細節，例如「停車壓力低｜綜合推薦高」。

卡片不以整張區域作為 Google 地圖連結，避免和查看歷史的互動衝突。

## 後端分析與狀態

既有 `analysis.py` 繼續負責停車壓力、距離、歷史摘要與推薦排序。新增一個純函式，把候選停車場轉成可顯示的決策資訊：

- `decision_status`: `recommended`、`warning` 或 `avoid`。
- `decision_label`: 對應的繁體中文結論。
- `reasons`: 最多三條白話原因。
- `pressure_label`: `低`、`中`、`高` 或 `極高`。
- `recommendation_label`: `高`、`中` 或 `低`。

狀態採互斥規則，避免同一停車場同時出現在推薦與避雷：

1. `avoid`：剩餘車位小於等於 3，或停車壓力大於等於 95。
2. `warning`：未被列為避雷，且停車壓力介於 85 到 94.99。
3. `recommended`：其餘有效候選，依既有綜合推薦分數排序。

每組最多顯示三張。若沒有低風險候選，推薦區顯示「目前沒有低風險停車場」，而不是把避雷場站包裝成推薦。

## 白話原因規則

原因由後端固定條件產生，不呼叫 Gemini：

- 空位為 0：`目前已滿場`。
- 空位小於等於 3：`目前只剩 N 格，抵達前可能滿場`。
- 壓力大於等於 85：顯示目前使用率及高滿場風險。
- 其他狀況：顯示 `目前 N / T 格可停` 與空位狀況。
- 距離小於等於 500 公尺：`距目的地近，約 N 公尺`。
- 距離 501 到 1,000 公尺：`距目的地約 N 公尺`。
- 超過 1,000 公尺：提示距離較遠。
- 歷史樣本達既有最低門檻：顯示同日別、同時段的歷史壓力。
- 歷史樣本不足：明確顯示 `歷史樣本不足，未納入判斷`。
- `warning`：加入 `建議保留下一個選擇` 的行動提示。
- `avoid`：加入 `建議改看推薦前往清單` 的行動提示。

## 地址與 Google 地圖

API 已回傳 `district`、`address`、`latitude` 與 `longitude`，不需修改資料表。

前端格式化完整地址時：

- 地址已包含「臺北市／台北市」時直接使用並正規化為「臺北市」。
- 地址以行政區開頭時，前面補「臺北市」。
- 其他地址組成 `臺北市 + district + address`。

Google 地圖連結優先使用座標：

`https://www.google.com/maps/search/?api=1&query=<latitude>,<longitude>`

若座標不存在，改用停車場名稱與完整地址作為 URL 編碼後的搜尋文字。地址連結與按鈕都使用新分頁，並設定 `rel="noopener noreferrer"`。Google Maps 網頁連結不需要 API key，也不增加付費服務。

## 前端修改範圍

- `static/app.js`：格式化地址、建立 Google Maps URL、渲染後端決策狀態與原因、保留歷史按鈕事件。
- `static/style.css`：加入狀態徽章、容量數字、空位比例條、原因區、雙操作按鈕及手機版樣式。
- `templates/index.html`：只在必要時補充區塊說明，不新增頁面。

前端不重新計算推薦分數，只顯示後端已決定的狀態與原因。

## 錯誤與缺少資料

- 地址缺少時顯示「地址資料未提供」，Google 地圖按鈕仍可在有座標時使用。
- 地址與座標都缺少時停用 Google 地圖操作。
- 總車位或剩餘車位無效的資料維持由後端排除，不渲染誤導性比例條。
- 歷史資料不足時保留查看歷史按鈕，但圖表顯示既有的樣本不足訊息。

## 測試與驗收

- 單元測試決策狀態互斥、臨界值、原因文字及分數標籤。
- 路由測試確認候選資料包含完整決策欄位、地址、總車位及座標。
- JavaScript 語法檢查通過。
- 瀏覽器人工驗收推薦、警示、避雷三種卡片，以及桌面三欄與手機單欄。
- 點擊地址與 Google 地圖按鈕會在新分頁打開正確位置；點擊查看歷史仍載入原有 Chart.js 圖表。

## 不在本次範圍

- Gemini 生成推薦理由。
- Google Maps API、路線導航或付費地圖服務。
- 修改推薦公式權重、AI 預測空位或新增資料表。
