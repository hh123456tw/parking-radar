# 停車結果頁精簡與決策規則設計

日期：2026-08-04  
狀態：使用者已選擇方案 A

## 目標

讓第一次使用者在結果頁先回答三件事：哪三座最值得去、目前還有幾格、為什麼值得去。降低重複分數、原因框與按鈕造成的雜訊，同時修正大型停車場只因使用率高就被標成「有滿場風險」的問題。

本次只調整既有分析規則與單頁結果呈現，不新增資料表、外部 API、前端框架或地圖套件。

## 結果頁資訊順序

1. 目的地與資料時間。
2. 目前區域停車狀況與有效停車場數量。
3. 三張首選停車場卡片。
4. 其他場站精簡列表。
5. 強化後的首選位置地圖。
6. 使用者主動選擇場站後才出現的歷史區塊。

首頁摘要不再把「首選場站抵達時段歷史」列為主要指標。地獄指數保留，但以「目前停車狀況」的文字標籤為主，分數降為輔助說明。

## 混合滿場規則

個別停車場不能只用使用率判斷，必須同時看剩餘格數與空位率：

```text
空位率 = available_spaces / total_spaces

不建議前往：
  available_spaces <= 3

建議備選：
  available_spaces <= 15 且空位率 < 50%
  或 available_spaces <= 30 且空位率 < 10%

可以前往：
  其他有效資料
```

規則邊界採包含判斷。例如 3 格為不建議、15 格且空位率 49% 為建議備選、30 格且空位率 9% 為建議備選。

`148 / 1360` 的空位率約 10.9%，且絕對空位有 148 格，因此分類為「可以前往」，理由顯示「目前仍有 148 格，空位數充足」，不得再顯示「滿場風險偏高」。地獄指數與推薦分數仍可用於區域壓力及排序，但不得單獨決定個別場站的滿場標籤。

## 三張首選卡片

只將 `recommendations` 的前三筆呈現為完整卡片。若不足三筆就顯示實際筆數，不得把風險場站冒充首選。

每張卡片依序顯示：

- 首選名次、狀態與距離。
- 停車場名稱。
- 可點擊並開啟 Google 地圖的完整地址。
- 大字顯示「目前可停格數」，小字顯示「總車位數」。
- 空位比例條。
- 一句主要判斷，例如「目前仍有 148 格，距目的地 671 公尺」。
- Google 地圖主要操作。
- 「查看空位趨勢」次要操作。

完整卡片移除重複的三點理由框，以及「停車壓力高｜綜合推薦低」等首次使用者無法直接採取行動的抽象分數文字。既有後端分數欄位可保留，不需要擴大 API 改動。

## 其他場站精簡列表

`warning` 與 `avoid` 最多各三筆，合併在「其他附近場站」區塊。每列只顯示：

- 狀態標籤。
- 停車場名稱。
- 剩餘格數／總格數。
- 距離。
- Google 地圖連結。

列表不重複顯示完整原因面板或大型橘色按鈕。警示與不建議仍使用黃、紅狀態色，但文字必須同時存在，不能只靠顏色傳達。

## 歷史資料按需顯示

查詢完成後不再自動載入第一名停車場歷史。只有使用者點擊「查看空位趨勢」才呼叫既有歷史 API。

- 少於 8 筆有效資料：隱藏 canvas，顯示「歷史資料累積中，目前 N 筆；累積 8 筆後顯示趨勢」。
- 8 筆以上：顯示所選停車場名稱、資料筆數與折線圖。
- 圖表容器桌面高度最多 280px，避免少量資料撐滿整個頁面。
- 切換停車場時更新標題、空狀態或圖表，不新增第二張圖。
- 歷史資料只做參考，不宣稱預測未來空位。

## 地圖強化

不新增地圖套件，沿用 Leaflet：

- 目的地維持獨立藍色標記並標示「目的地」。
- 三個首選使用較大的實心綠色圓形標記，中央永久顯示 1、2、3。
- 警示與不建議場站使用較小的黃、紅標記並降低視覺權重。
- 地圖視野優先包含目的地與三個首選；沒有首選時才納入其他有效場站。
- 右側由「距離最近」改為「首選位置」，顯示相同名次、場站、空位與距離。
- 點擊右側項目時，地圖移動到該場站並開啟 popup。

標記同時使用名次、大小、色彩與文字，避免只靠細小色圈辨識。

## 空狀態與錯誤處理

- 沒有首選但有其他場站：清楚顯示「目前沒有低風險首選」，仍提供精簡列表與地圖。
- 完全沒有候選：顯示資料時間與重新查詢提示，不渲染空卡片或空圖表。
- 歷史 API 失敗：只在歷史區塊顯示錯誤，不覆蓋已完成的推薦結果。
- Gemini、地址搜尋與即時資料流程不因本次 UI 精簡而改動。

## 響應式與可及性

- 桌面顯示三欄首選卡；窄螢幕改為單欄。
- 其他場站列表在手機上改成可換行的單列卡片。
- 所有狀態都有可讀文字，不以綠、黃、紅作為唯一訊息。
- 地圖列表與按鈕維持鍵盤可操作，互動元素保留清楚焦點樣式。
- 動態摘要與歷史狀態使用既有可讀狀態區域，不新增自動跳焦點。

## 程式邊界

- `analysis.py`：只修改個別場站決策分類與白話理由。
- `static/app.js`：拆分首選卡、其他列表、地圖與按需歷史渲染。
- `static/style.css`：調整資訊層級、精簡列表、歷史高度與地圖標記。
- `templates/index.html`：重排摘要、其他場站、地圖側欄及歷史空狀態。
- `app.py` 與資料庫 schema 原則上不需變更；若前端可沿用現有欄位，不新增 API 欄位。

不新增 JavaScript 框架、CSS 框架、地圖外掛、資料表或 Gemini 分析責任。

## 測試與驗收

自動測試：

- 參數化測試滿場規則的 3、4、15、16、30、31 格邊界與空位率條件。
- 回歸測試 `148 / 1360` 必須是「可以前往」，且理由不得包含「滿場風險偏高」。
- 前端契約測試確認不再自動呼叫歷史 API、少於 8 筆隱藏圖表、首選與其他列表分開。
- 前端契約測試確認地圖具有首選名次標記與點擊側欄定位行為。
- 完整 pytest、Python compileall 與 `node --check` 必須通過。

人工驗收：

- 桌面版第一個視窗內能看懂三個首選及主要空位數。
- `148 / 1360` 不再顯示高滿場風險。
- 三筆歷史資料只顯示累積提示，不顯示大面積平線圖。
- 地圖上的目的地與三個首選可立即區分，點擊側欄可開啟對應 popup。
- 手機版維持單欄、無水平捲動，Google 地圖連結仍可操作。

## 不在本次範圍

- 改變 Gemini 主模型或對話備援機制。
- 新增路邊車格、導航、會員或民營停車場爬蟲。
- 重寫推薦公式、地圖底圖或資料收集排程。
