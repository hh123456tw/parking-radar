# ADR 0003：快照先封存驗證，再從 MySQL 刪除

- 狀態：採用
- 日期：2026-09-13

## 背景

Collector 每 15 分鐘寫入約一千筆快照，MySQL 只需保留近期資料供查詢與趨勢圖使用；但完整歷史未來可能用於分析，不能直接刪掉。

## 決策

每日清理以完整 UTC 日期為單位：

1. 串流寫出 `parking-snapshots-YYYY-MM-DD.csv.gz` 暫存檔，完整讀回驗證列數與欄位後 `fsync`。
2. 以 `os.link` 發布正式檔（create-only，不會覆蓋既有封存），再寫入含列數與 SHA-256 的完成證明（manifest）。
3. 只有封存與完成證明都驗證通過，才分批刪除該日快照。
4. 若程序在發布 CSV 後、寫入完成證明前中斷，下次執行會重新讀取資料庫；內容與 CSV 完全一致才補寫證明，否則拒絕刪除。

## 影響

- 任何一步失敗都停在「多保留資料」的一側，不會刪掉未封存的快照。
- 網站查詢不讀封存檔，封存不影響線上效能。
- 代價：封存目錄需要監控磁碟空間（低於 1 GiB 時拒絕寫入）。
